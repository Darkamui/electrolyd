## Traps confirmed on this build

### 1. Cycles is invisible to the static engine enum

`bpy.types.RenderSettings.bl_rna.properties["engine"].enum_items` returns only
`['BLENDER_EEVEE']`. **This does not mean Cycles is missing.** Cycles registers
dynamically as an add-on. Verified present and enabled.

```python
# WRONG - will wrongly conclude Cycles is unavailable
engines = [e.identifier for e in prop.enum_items]

# RIGHT - assignability is the real test
scene.render.engine = "CYCLES"
assert scene.render.engine == "CYCLES"
```

Dynamically registered engines here: `HydraRenderEngine`, `CYCLES`.

### 2. Cycles defaults to CPU — GPU must be set explicitly

`scene.cycles.device` is `'CPU'` out of the box. **OPTIX is available** and is
the right backend for this RTX card (hardware ray tracing). Hero renders must
opt in or they will be needlessly slow:

```python
prefs = bpy.context.preferences.addons["cycles"].preferences
prefs.compute_device_type = "OPTIX"          # CUDA also available
for d in prefs.get_devices_for_type("OPTIX"):
    d.use = True
scene.cycles.device = "GPU"
```

Ignore the startup warnings: HIP fails (no AMD card) and the Intel iGPU driver
is too old. Neither matters — OPTIX on the NVIDIA card is the target.

### 3. `mesh.use_auto_smooth` no longer exists

Removed in 4.1. `hasattr(mesh, "use_auto_smooth")` is **False** here.

```python
bpy.ops.object.shade_smooth()                    # works
bpy.ops.object.shade_auto_smooth(angle=0.5236)   # USE THIS for 30° auto smooth
```

### 4. Principled BSDF socket names — the 4.0 rename is in effect

There is **no** `Specular`, `Emission`, `Subsurface`, or `Transmission` socket.
Writing to those names raises `KeyError`. Full verified socket list:

```
Base Color · Metallic · Roughness · IOR · Alpha · Thin Wall · Normal · Weight
Diffuse Roughness
Subsurface Weight · Subsurface Radius · Subsurface Scale · Subsurface IOR
  · Subsurface Anisotropy
Specular IOR Level · Specular Tint · Anisotropic · Anisotropic Rotation · Tangent
Transmission Weight
Coat Weight · Coat Roughness · Coat IOR · Coat Tint · Coat Normal
Sheen Weight · Sheen Roughness · Sheen Tint
Emission Color · Emission Strength
Thin Film Thickness · Thin Film IOR
```

Mapping for the materials we need: molten aluminium glow →
`Emission Color` + `Emission Strength`; bath translucency →
`Transmission Weight`; steel highlight → `Specular IOR Level`.

### 5. Transforms are float32 — never assert tighter than 1e-6

Found by `tools/lib_test.py`. A box placed at exactly 830 mm reads back as
`0.8299999833106995`, not `0.830`. Blender stores object transforms in single
precision.

```python
assert abs(obj.location.z - expected) < 1e-9   # WRONG - fails every run
assert abs(obj.location.z - expected) < 1e-6   # RIGHT
```

**This governs every QA clearance check.** Asserting the 45 mm ACD or the
30 mm ledge/anode gap to nanometre precision would produce permanent false
failures. `qa/validate.py` uses a 1e-6 m (0.001 mm) tolerance throughout —
still four orders of magnitude finer than any real dimension in the datasheet.

### 6. View transforms are also invisible to their static enum

Same trap as Cycles (#1), different property. OCIO registers colour transforms
dynamically, so the static enum is useless:

```python
prop = scene.view_settings.bl_rna.properties["view_transform"]
[e.identifier for e in prop.enum_items]   # -> ['NONE']   (misleading)
scene.view_settings.view_transform        # -> 'AgX'      (the truth)
```

**AgX is the default on this build** and is what the render tiers want, so
`render/shots.py` sets it defensively inside a `try` and is correct either way.
Generalised rule: on this build, never conclude a feature is absent from an
`enum_items` listing — read the live value, or test assignability.

### 7. `bpy.types.MeshEdge` has no `link_faces`

`link_faces` / `link_edges` are **bmesh** attributes. To test manifoldness on
an evaluated mesh you must round-trip through bmesh:

```python
bm = bmesh.new(); bm.from_mesh(obj.data)
manifold = all(len(e.link_faces) == 2 for e in bm.edges)
bm.free()
```

## Confirmed working — safe to rely on

| Capability | Note |
|---|---|
| `mesh.from_pydata` + `bmesh` ops | Both fine for authored geometry |
| Nested collections | `parent.children.link(child)` — the 13-collection tree is fine |
| **Linked duplicates share mesh data** | 5 objects → 1 mesh datablock, `users=5`. This is what makes 36 anodes cheap |
| Modifiers | BEVEL (`limit_method`/`angle_limit`), SOLIDIFY, MIRROR (`use_axis`), ARRAY (`use_constant_offset`), BOOLEAN (`solver="EXACT"`) |
| Custom properties + UI range | `obj.id_properties_ui("Explosion").update(min=, max=)` |
| **Drivers** | SCRIPTED expression reading `["Explosion"]` via SINGLE_PROP evaluates correctly (`is_valid=True`). The explosion rig is viable as designed |
| Orthographic cameras | `type="ORTHO"`, `ortho_scale` — needed for the front/side/top plates |
| EEVEE render to PNG | Engine id is `BLENDER_EEVEE` (not `_NEXT` on this build). Use for fast iteration renders |
| glTF export | All required kwargs present, including `export_draco_mesh_compression_enable`. Draco is available for the WebGL build |
| `.blend` save | Fine |

## Render strategy implied by the above

- **Iteration renders** → EEVEE (`BLENDER_EEVEE`), low res, fast feedback loop
- **Hero / QA renders** → Cycles on **OPTIX GPU**, denoising on
- **WebGL export** → glTF with Draco, from the separate optimized path
